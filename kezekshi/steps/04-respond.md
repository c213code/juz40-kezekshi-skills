# 4-қадам. Шешім, эскалация және жауап

**Мақсаты:** өтінішті жабу — кім не істейтінін анықтау және авторға жауап беру.

## Шешім кестесі

| Себебі | Не істейміз | Кім жасайды |
|---|---|---|
| Солай ойластырылған | Ережені түсіндір, болса айналып өту жолын ұсын | Кезекші |
| Пайдаланушы құрылғысы | Түсінікті нұсқаулық | Кезекші |
| Бір пайдаланушының деректері | Түзетуді дайында (SQL/curl), нені өзгертетінін түсіндір | Скилл дайындайды → әзірлеуші растап орындайды |
| Кодтағы баг | Пайдаланушыға уақытша жол + Jira (`bag-jira` скиллі) | Кезекші + әзірлеуші |
| Жаппай ақау / ақша | Бірден кезекші әзірлеушіге; чатқа «білеміз, түзетіп жатырмыз» | Шұғыл |
| Сыртқы сервис | Жеткізушіге/әзірлеушіге хабарла, пайдаланушыға түсіндір | Әзірлеуші |

## Түзету дайындау ережелері

1. Алдымен `SELECT` — неше жол табылатынын көрсет.
2. Содан кейін `BEGIN; UPDATE ... ; COMMIT;`, `WHERE` ішінде тек `id` және күй шарты
   (мысалы `AND status = 'REJECTED'`) — қайта іске қосу қауіпсіз болсын.
3. Күтілген жол санын жаз: «UPDATE 1 болмаса — ROLLBACK».
4. Қай кэшті тазалау керегін жаз (бір нақты кілт, циклсіз).
5. Түзетудің жанама әсерін ескерт (мысалы, кейін қайта есептеу қолмен қойылған балды
   өшіруі мүмкін).

## Шығыс

```
Шешім: ...
Кім жасайды: кезекші / әзірлеуші / Jira
Растау керек пе: иә/жоқ (нені)
Чатқа жауап: (бөлек блок, дайын мәтін)
```

## Чатқа жауап ережелері

1. Чаттың тілінде (әдетте қазақша), қысқа, техникалық терминсіз.
2. Не анықталды → не жасалды / жасалады → олардан не керек.
3. Шешім болмайынша уәде берме: «ертең түзеледі» емес, «әзірлеушілерге тапсырдық».
4. Кодта баг болса — алдымен айналып өту жолы.
5. Автор жауап алмайынша өтініш жабылған жоқ.
