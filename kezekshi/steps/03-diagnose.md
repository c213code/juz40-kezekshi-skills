# 3-қадам. Диагностика

**Мақсаты:** себебін табу — шешім соған байланысты.

## Тексеру реті (арзаннан қымбатқа)

1. **Солай ойластырылған ба?** Дедлайн, рөл бойынша қолжетімділік, тариф, лимит.
   Кодтан шешім қабылданатын ережені тап.
2. **Пайдаланушының деректерінде ме?** Басқа топта, статусы басқа, төлем өтпеген,
   аккаунт екеу. Жұмыс істеп тұрған пайдаланушымен салыстыр.
3. **Пайдаланушының құрылғысында ма?** Браузер, ескі нұсқа, құрылғы уақыты, интернет.
4. **Кодта ма?** Шешім қабылданатын орынды тауып, неге қате екенін түсін.
5. **Сыртқы сервисте ме?** Төлем, қолтаңба, SMS, видео.

## Логтар

Логтарды `scripts/logs.py` арқылы ізде (өрістер: `references/logs.md`):

```bash
# Скринде Request ID болса — ең дәл жол
python3 scripts/logs.py --request-id <ID>

# Request ID жоқ: пайдаланушы + өтініш уақыты ±15 мин, тек қателер
python3 scripts/logs.py --user <почта> --at "2026-11-18 14:20" --minutes 15 --errors

# Ауқымы: соңғы 1 сағатта осы endpoint-те қате алғандар
python3 scripts/logs.py --mapping "/v1/..." --since 1h --errors --count-users
```

`--at` уақыты Алматы уақытымен беріледі; скрипт өзі UTC-ге аударады.

## Шығыс

```
Себебі: ... (қарапайым тілмен)
Түрі: ойластырылған / деректер / құрылғы / кодтағы баг / сыртқы сервис
Дәлел: дерек / лог (Request ID) / код орны (файл:жол)
Ауқымы: тек осы пайдаланушы / тағы N адам
```

## Ережелер

1. Қорытынды тексерілген фактіге сүйенеді. Расталмаса — «расталмады» деп жаз.
2. Алдымен арзан болжамдар, содан кейін код.
3. Себебі табылған соң — ауқымын тексер.
4. Түсіндірме әзірлеуші емес адамға түсінікті болсын.
5. Тек оқу. Логтан сұраныс/жауап денесін, токенді, парольді шығарма.
