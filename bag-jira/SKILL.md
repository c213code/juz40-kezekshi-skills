# Багты Jira-ға

Бір рет түзетілген мәселе чатта жоғалып кетпеуі үшін — оны тапсырмаға айналдыр.
Скиллді кезекші, QA, әзірлеуші, менеджер қолдана алады.

## Кіріс

- `kezekshi` скиллінің нәтижесі (карточка, қайталау қадамдары, себебі), немесе
- чаттағы баг сипаттамасы (онда алдымен kezekshi-дің 1–3 қадамын қысқаша өт).

## Не істейсің

1. **Дубльді тексер.** Jira-да (Atlassian MCP) ұқсас тапсырманы кілт сөздермен ізде.
   Бар болса — жаңасын ашпа, барына пікір қосуды ұсын (жаңа жағдай, ауқым).
2. **Ауқымын сана.** Дерекқор (тек оқу) немесе логтар арқылы: қанша пайдаланушыға,
   қай кезеңде әсер етті. Санау мүмкін болмаса — «бағаланбады» деп жаз.
3. **Тапсырма мәтінін жаз** (төмендегі үлгі).
4. **Кезекшіге көрсет және растауын ал.** Тек содан кейін Jira-да жаса.
5. Тапсырма сілтемесін чатқа жауапқа қос (қажет болса).

## Тапсырма үлгісі

```
Тақырып: <пайдаланушы тілінде: не бұзылды, кімге әсер етеді>

## Не болып жатыр
<1–2 сөйлем>

## Қайталау қадамдары
Алғышарттар: ...
1. ...
Күтілген нәтиже: ...
Нақты нәтиже: ...

## Ауқымы
<N пайдаланушы / кезең / қалай саналды>

## Дәлел
- Лог: Request ID ..., уақыты ...
- Код: <файл:жол> — <не дұрыс емес>
- Дерек: <кесте, қандай белгі>

## Ұсыныс
<түзету идеясы> / Уақытша айналып өту жолы: ...

## Өтініштер
<қай чаттан, қашан (жеке деректерсіз)>
```

## Ережелер

1. Ауқымы санап жазылады: «кейбір оқушыларда» емес, «соңғы 30 күнде N оқушы».
2. Бір себеп — бір тапсырма. Ұқсас өтініштер бір тапсырмаға жиналады.
3. Тақырып пайдаланушы тілінде: «Квиз тапсырылса да балл қойылмайды», не «progress status null».
4. Тапсырмада пароль, токен, жеке деректер (почта, телефон, ИИН) болмайды —
   пайдаланушыны ID-мен немесе «оқушы A» деп белгіле.
5. Міндетті өрістер: түрі (Bug), орындаушы, бағалау, спринт — команданың Jira
   тәртібі бойынша. Білмесең — кезекшіден сұра, болжама.
6. Jira-да тапсырманы тек кезекші растағаннан кейін жаса.
