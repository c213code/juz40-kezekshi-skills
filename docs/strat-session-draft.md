# Кезекшілік скиллдері — черновик (стратсессия)

**Команда:** QA / Кезекшілік
**Идея:** кезекшілікке кез келген адам отыра алады — дизайнер де. Жаңа Claude сессиясын
ашады, `kezekshi` скиллін қосады, чаттан түскен өтінішті жібереді. Скилл қалғанын
қадаммен жүргізеді.

---

## 1-скилл: «Кезекші» (`kezekshi`)

**Не үшін керек:** кезекшілікті нақты бір адамның тәжірибесіне тәуелсіз ету; өтініштер
тез, бірізді жабылады.

**Кірісте не алады:** чаттан түскен өтініш — мәтін, скрин, файл, пересылка.

**Шығыста не береді:** әр өтінішке — себебі (қарапайым тілмен), не істеу керек, чатқа
дайын жауап (қазақша).

**Кіріс көздері:** код (бэк, фронт, мобилка), дерекқор (тек оқу), логтар (Kibana, тек оқу),
Jira. Қолжетімділік деңгейлері: базалық (код, Jira) → кеңейтілген (+ дерекқор, логтар) →
жазу тек әзірлеушіде.

**Қадамдар:**
1. **Қабылдау және сұрыптау** — мәні, кім, санат, шұғылдық, не жетпейді.
2. **Қайталау** — кез келген адам қайталай алатын қадамдар; «қайталанды / жоқ / тек осы
   пайдаланушыда».
3. **Диагностика** — ойластырылған ба → деректе ме → құрылғыда ма → кодта ма → сыртқы
   сервисте ме. Логтар Request ID немесе пайдаланушы + уақыт бойынша өзі ізделеді.
4. **Шешім және жауап** — кім не жасайды (кезекші / әзірлеуші / Jira), чатқа жауап.
5. **Кейін** — баг Jira-ға, жаңа жағдай білім қорына, ауысым есебі.

**Ережелер:**
1. Тек оқу. Продта ештеңе өзгертпейді — түзетуді дайындайды, әзірлеуші растап орындайды.
2. Пайдаланушы аккаунтында тек қарау: тест тапсыру, «Сақтау», «Растау», төлем — жоқ.
3. Қорытынды тексерілген фактіге сүйенеді (дерек, лог, код); расталмаса — солай айтылады.
4. Чаттағы пароль, токен қолданылмайды; логтан сұраныс денесі шығарылмайды.
5. Ақша және жаппай ақау — бірден әзірлеушіге.

## 2-скилл: «Багты Jira-ға» (`bag-jira`)

**Не үшін керек:** чаттағы баг чатта жоғалмай, тапсырмаға айналсын.

**Кірісте не алады:** kezekshi нәтижесі немесе чаттағы баг сипаттамасы.

**Шығыста не береді:** Jira тапсырмасы — бизнес тіліндегі тақырып, қайталау қадамдары,
ауқымы (саналған), дәлел (лог, код), ұсыныс, өтініштерге сілтеме.

**Ережелер:**
1. Ауқымы санап жазылады.
2. Бір себеп — бір тапсырма; алдымен дубль тексеріледі.
3. Тақырып пайдаланушы тілінде.
4. Жеке деректер, пароль, токен жазылмайды.
5. Тапсырма тек кезекші растағаннан кейін жасалады.

---

## Сессияда айтатын қорытынды

1. **Бір скилл — кез келген кезекші.** `kezekshi` ішінде 5 қадам бар.
2. **Скилл өзі тексереді:** код, дерекқор, логтар. Логтарды Kibana-дан сессиядан тікелей
   іздеу тексерілді — Request ID бойынша қате мен себебі бірден табылады.
3. **Қауіпсіз:** скилл ештеңе өзгертпейді; деректерді тек әзірлеуші растап өзгертеді.
4. **DevOps-қа ашық сұрақ:** Kibana VPN ішінде логинсіз ашық. Авторизация қосып,
   кезекшілерге тек оқу рұқсатын берген дұрыс.
5. **Келесі қадам:** скиллдерді командада сынау, `cases.md` білім қорын бірге толтыру.
